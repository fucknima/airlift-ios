# airlift-ios

iPhone-only operation of the AirLift write primitive, no Mac in the loop.

Two halves:

- pairing: the app advertises `_remotepairing-pairable-host._tcp`, iOS 27 pairs with it on-device, and the resulting RPPairing record is stored in the app container. No computer, no imported file.
- transport: a loopback utun (LocalDevVPN) puts the device's own developer services on `10.7.0.1:49152`; the app opens an RPPairing tunnel to itself, does the RSD checkin, and talks to the device's shim services.

Status:

- wave 1, in this tree: pairing, record store/import, LocalDevVPN control, tunnel, RSD service listing, AFC device info.
- wave 2, next: the AirLift transport proper. `streaming_zip_conduit` staging, `atc` Books sync, AFC readback, canary verification, cleanup. Protocol notes are in `docs/PROTOCOL.md`.

## requirements

- iPhone on iOS 27 for on-device pairing. On older builds, import an RPPairing file generated by `idevice_pair`.
- LocalDevVPN (App Store, free) for the loopback route.
- macOS with Xcode and xcodegen to build, or the GitHub Actions workflow in `.github/workflows/build.yml`.
- A signing path for the device: free developer account, SideStore/AltStore, or a paid team. The output of `scripts/build.sh` is unsigned.

## build

GitHub Actions, macOS runner, unsigned IPA:

```sh
git remote add origin git@github.com:<you>/airlift-ios.git
git push -u origin main
```

`.github/workflows/build.yml` runs on every push to `main`, builds the idevice
FFI from a pinned commit, caches it, builds the app, and uploads
`airlift-unsigned-<sha>.ipa` plus `build.log`. Pushing a `v*` tag also creates a
release with the IPA attached.

Local build, same script:

```sh
brew install xcodegen rustup
rustup target add aarch64-apple-ios
./scripts/build.sh
```

`scripts/build-ffi.sh` clones `jkcoxson/idevice` at commit `8970209`, builds
`libidevice_ffi.a` for `aarch64-apple-ios` with `afc,tunnel_tcp_stack,ring`,
generates the matching header, and refuses to continue if the AFC, pairable
host, tunnel, or RSD symbols are missing. Then xcodegen and xcodebuild produce
`Airlift-unsigned.ipa`.

The IPA is unsigned. Sign it with a free developer account, SideStore/AltStore,
or a paid team before installing. No special entitlements are requested, so a
plain development profile is enough.

## run

1. Install the IPA.
2. Open Airlift, tap `Pair on this iPhone`, and enter the PIN shown in the app into the system pairing sheet.
3. Open LocalDevVPN and connect. It should hand out an address in `10.7.0.0/24`.
4. Back in Airlift, `Connect and list services`. A good run prints `com.apple.afc.shim.remote`, `com.apple.atc.shim.remote`, `com.apple.streaming_zip_conduit.shim.remote`, and the `com.apple.coredevice.fileservice.*` entries.
5. `AFC device info` proves the tunnel is authorized, not just open.

Background audio keeps the app alive through pairing and transfers. The app has no location or photo permissions and does not need Developer Mode.

## boundaries

- no container browsing, no `house_arrest`, no `bad_query`, no kernel exploit.
- the only write primitive in scope is the AirLift symlink path in Media plus the Books sync that follows it.
- the PoC's build gate (`24A437`) is not baked in; the app reports what the device gives back and refuses to stage when the expected Books objects are not reachable.
